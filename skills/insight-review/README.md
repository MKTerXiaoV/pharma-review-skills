# 洞察体检 · insight-review

> 体检系列 · MKTer 小V · 一起进化
> **v0.1.1 · 免费开源版**

审一条洞察或一份洞察材料**立不立得住**。不替你挖洞察。

洞察不是玄学,是可以练习的。一句自称"洞察"的话,先问它四个问题:去掉主语还成立吗?所以呢?指得出人和场景吗?反过来说有人辩护吗?

## 怎么装

**最简单(把这段甩给你的 AI agent):**
> 帮我把 https://github.com/MKTerXiaoV/insight-review 这个仓库整个导入为技能。要连 references 文件夹一起导入,不要只导 SKILL.md。

**自己装(Claude Code / 任意支持 Agent Skills 的工具):**
```bash
git clone https://github.com/MKTerXiaoV/insight-review ~/.claude/skills/insight-review
```

想把体检系列一起装齐,见全家桶 [pharma-review-skills](https://github.com/MKTerXiaoV/pharma-review-skills)。

## 怎么用

把那句洞察、或那一页客户洞察整段粘进去,说一句"用洞察体检帮我看看"。一句话也能审。给市场部的使用介绍见 `PRODUCT.md`。

## 它审什么

| 刀 | 判什么 |
|---|---|
| **四筐归位** | 这句话是现象、常识、金句,还是洞察 |
| **穿透力三段** | 看到什么 → 为什么 → 不管它会怎样,三段齐不齐 |
| **反证卡三行** | 表面解释是什么 / 它解释不了哪个事实 / 什么证据会推翻它 |
| **证据角色 + 场景信任梯度** | 支撑是医生"做的"还是"说的",在什么场合说的 |
| **生意闸门** | 这条改变了哪一个具体的生意动作 |
| **伪洞察黑名单九条** | 逐条标命中/未命中,不许只报命中的 |
| **合规红线五条** | 前置一票否决 |

## 守窄边界(写死)

不挖洞察(归生成侧) · 不审数读得对不对(归业务分析体检) · 不审策略落不落地(归 BP 策略体检) · 不审表达响不响(归关键信息体检)。

## 改判据的规矩 🚨

改任何判据后**必须回跑 T2、T6 和 T7**:
- **T2** 防"给真雷发通行证"——加正向判据时,模型会把个体医生处方行为当成亮点放行;
- **T6** 防"误杀真洞察"——跨品类也成立不等于常识;
- **T7** 防"反面测试被用歪"——通过反面测试不等于放行。

## 在流水线里的位置

证据体检 → 业务分析体检 → **洞察体检** → BP 策略体检 → 关键信息体检 → 活动设计体检 → 汇报体检
